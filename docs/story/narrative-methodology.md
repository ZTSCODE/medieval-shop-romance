# 叙事协作方法论

2026-10-03 建立。用户要求：故事内容**直接用英文写，英文写完并定稿后再翻成中文**；参考《绝对魔权》(Absolum) 的设定风格、叙事方式、氛围、结构、吸引点、异世感、命名方式和节奏，但不照抄它的剧情；主角能力必须和玩法挂钩；先写英文，再出中文。本文是长期写作规则，具体剧情放在同目录的其他草稿里。

---

## 1. 《绝对魔权》拆解：借鉴什么，不借鉴什么

资料来源见文末。标注“推断”的条目是我对公开资料的解读，并非开发者原话。

### 1.1 世界观的骨架

| 手法 | Absolum 的做法 | 好在哪里 |
|---|---|---|
| 暴政有合理来由 | 18 年前，巫师追求禁忌知识，引发“大灾变”(The Cataclysm)，民众从此不再信任魔法；太阳王阿兹拉借这股恐慌上台，建立腥红教团压制巫师 | 反派不是凭空作恶。他利用的是一种真实存在的恐惧，所以玩家会犹豫 |
| 后期反转 | 阿兹拉真正的目的是封住一个名为 Absolum 的异界存在；带领反抗的乌查维其实是他怀着孩子的妻子 | 反转让前面所有冲突换了一层意思，而不是单纯推翻前文 |
| 历史分层 | 龙主统治 → 各部族起义 → 根之姐妹会主政 → 大灾变 → 腥红教团 | 世界在主角出现以前就有很长的过去；遗迹、口头称呼和旧仇都有出处 |
| 魔法不可控 | 魔法源自混沌的异界 Mynasthar，被描述为狂野、无法理解的力量；有些仪式代价很重（复活需要夺走另一条命） | 魔法让人敬畏，而不是一套说明书 |

### 1.2 叙事的交付方式

- **少用过场动画**。剧情主要靠角色对话推进；另有可选的旧事碎片（在场景里的火光处听乌查维讲塔拉姆的历史）。
- **玩法循环本身被写进了世界观**。在肉鸽玩法里，角色每次死亡后被乌查维复活、重新出发，这件事是剧情的一部分，而不只是游戏规则。（推断：这是它“玩法与剧情不割裂”的核心。）
- **据点会成长**。每一轮出征都可能为“乌查维的炉边”带回新的 NPC，在那里可以交谈、解锁个人任务。剧情片段作为奖励，吸引玩家再出发。
- **个人支线**。每位可选角色都有自己的任务线。

### 1.3 命名方式（推断，依据为公开名单）

| 层级 | 例子 | 规律 |
|---|---|---|
| 大概念用真实古语，背后有含义 | Talamh（爱尔兰语“土地”）、Uchawi（斯瓦希里语“巫术”）、Namtar（美索不达米亚的死神）、Yarikh（乌加里特的月神）、Maugis（法兰西史诗里的魔法师）、Pass of Roncevalles（《罗兰之歌》中的山口） | 名字听起来古老、陌生，但懂的人能看出意思；每个名字只取一个来源，不拼接 |
| 人物用“名字 + 职业或外号” | Wisshelm the Archivist、Namtar the Turncoat、Zafari the Bandit Queen、Ambys, Defiant Slave Queen | 玩家看头衔就知道这个人做什么，名字本身可以陌生 |
| 常用的地方和东西用平实的英文 | The Melting Pot（酒馆）、Endless Bazaar、Vault of Memories、The Citadel | 玩家天天打交道的东西，一看就懂 |
| 故意放一些滑稽的名字 | Guy Zorg, Cosmic Brother of Gazorg、City of Sh'norkle、Axolotl Masseuse | 在宏大黑暗的气氛里留出生活感和笑点 |

### 1.4 异世感的来源

- **怪事被当作平常事**：一只青蛙巫师、机械肢体的刺客、一个美西螈按摩师都没人觉得奇怪。陌生感来自角色的不惊讶，而不是来自旁白的惊叹。
- **美丽的衰败**：繁茂的森林长在金属废墟上。
- **道德灰度**：没有一方完全干净。

### 1.5 不借鉴的部分

- 评论普遍认为 Absolum 的剧情“隐晦、偏冷、交代单薄”，人物塑造让位于战斗。本作以人际关系和恋爱为核心，必须反过来：**世界观骨架学它，人物温度要远远超过它**。
- 不使用它的任何专名、种族设定、剧情事件，也不做清版动作那种高强度的战斗节奏。

## 2. 本作的写作规则

### 2.1 先有玩法，再有设定

每个核心机制都必须在世界里有一个说法，让玩家做的事情就是主角在故事里做的事情。新设定动笔前，先在下表补上一行；补不上，就说明这个设定是硬缝进去的。

| 玩法 | 世界里的说法 | 状态 |
|---|---|---|
| 卡牌叠放合成 | 只是玩法，不是主角的剧情能力；主角是没有超能力的普通人（2026-10-03） | 用户已确认 |
| 开店 | 他在背风地开店谋生；货从合成、探索和交易里来 | 提案 |
| 主角 + 地点 = 探索 | 走过去，把找到的东西带回来（不涉及魔法） | 提案 |
| 主角 + NPC = 交谈 | 两个人待在一起 | 提案 |
| 一切都是卡牌 | 只是游戏的表现形式，故事里不解释，也不为它造词 | 用户已确认 |

### 2.1.1 文学性的度（2026-10-03 用户要求）

要像真正的文学作品：既不能太口水（magic police、magic licence），也不能为怪而怪（leaf、Unwritten Wood 这类生造概念）。做法是用历史上真实存在、带着分量的词（assize、warden、hedge-maker、the Good People），只给专名做发明；人文、历史、宗教、经济、习俗都要先设定好，台词里只露一角。具体对照表和文学标杆见 `world-bible.md` 第 0 节。

### 2.2 命名规则

1. **按文化分音系**。帝国用拉丁语系，读音硬、偏公文腔；林中与村落用盖尔语系（爱尔兰语、苏格兰盖尔语、威尔士语），只取读音简单的词，必要时按英语习惯拼写。
2. **一个名字只取一个来源，并且有含义**。在命名表里写清楚出处和意思。不把两种语言的词根拼成一个新词。
3. **人物按“名字 + 职业或外号”命名**。卡牌和对话框可以先只显示职业（如“守林人”），知道名字以后再显示全名。
4. **日常地点和物品用平实的英文**：Badger Track、The Stones。中文同样用平实的说法。
5. **每个名字都要过五关**：大声读三遍不拗口；和已有名字的首字母、读音不撞；搜索一下，没有撞上知名作品里的人物；中文译名不像网文；能用一句话说清楚为什么叫这个名字。
6. **中文翻译要像中世纪西方奇幻，不能像古风**：参照西方奇幻小说常见的中译习惯。专名音译，选常见字；职务和机构用现代通用词意译。禁止使用古汉语和中国官制词汇（册、吏、府、司、碑、执达吏、书吏之类），也不自造“司名”“执灯人”这类四字词。中文版要等英文定稿后再统一翻译，翻译时先定一张译名表，交给用户确认。
7. **每一场最多出现一个需要理解的新概念**；人名和头衔一起出现时，算作一个。一听就懂的背景地名（河、镇）不计入，但必须取自 `world-bible.md` §6a 的地名表，并且以后会反复出现。
8. **外部世界靠反复提及变得可信**：一个地名第一次出现时不解释；至少两个不同的角色提到它之后，才允许有人解释。不为一句台词新造地名。

### 2.3 结构与节奏

- **从事件中间开场**，先行动，后解释。开场不讲历史。
- **一场戏只做一件事**：有人想要什么，被什么挡住，最后有什么变化。
- **每 6–10 句对白放一个笑点或生活细节**，用来缓和紧张或沉重。
- **补充资料放进卡牌说明**（对应 Absolum 的可选旧事碎片）。主线对白里不讲设定，想深挖的玩家去读卡牌说明。
- **剧情是推动玩家继续玩的奖励**：新 NPC 来到村子，新的对话片段就解锁，村子也随之慢慢热闹起来（对应 Absolum 会成长的据点）。
- **反转先埋伏笔**：每一个反转，都要在前面至少出现两次无害的线索。

### 2.4 人物与恋爱

- 张力来自具体的动作和眼神：手停留的时间多了半拍、目光落在哪里、一句没有说完的话。不用“你是我的”“玩火”这类台词，也不写油腻的挑逗。
- 每个可攻略角色都要有：一个与恋爱无关的欲望、一条不能越过的底线、一次主动的邀请、一次会被玩家看见的自我修正。
- NPC 不能说出他不应该知道的事情。
- 拒绝恋爱的玩家，仍然能拿到同等的玩法收益。

### 2.5 异世感

- 角色对怪事不惊讶。旁白不感叹“这真是神奇的世界”。
- 用具体的生活细节代替宏大的说明：硬币是什么做的、人们怎么骂人、孩子玩什么游戏。
- 帝国与林中的人对同一样东西有不同的叫法，从叫法就能听出立场。

## 3. 协作流程

| 步骤 | 谁来做 | 产出 | 通过标准 |
|---|---|---|---|
| 1 定前提 | Claude 提案，用户拍板 | `world-bible.md` | 2.1 的玩法对照表每一行都能补上 |
| 2 命名 | Claude 给每个名字 2–3 个候选，附出处 | 命名表 | 每个名字都过了 2.2 的五关 |
| 3 英文原稿 | Claude | 只写英文的剧本 | 自查第 4 节的清单 |
| 4 用户审读英文 | 用户 | 批注或修改意见 | 用户确认英文定稿 |
| 5 中文稿 | Claude 先出译名表，再翻译全文 | 中文译稿 | 用户确认译名表；没有古风词；读起来像原生写作 |
| 6 接入游戏 | Claude | 写入 `content.json`、本地化表和测试 | 实机截图，中英文都完整走一遍 |
| 7 回写 | Claude | 更新知识库 | 已确认的事项写进 `docs/knowledge/` |

用户只需要拍板前提、主要人物和语气；名字、台词细节、卡牌说明由 Claude 先提案，用户可以随时否决。被否决的方案记录在草稿的“历史”一节，不再自动复用。

## 4. 交稿前的自查清单

- [ ] 删掉角色名，还能分辨出每句话是谁说的吗？
- [ ] 删掉设定名词，这场戏的事件还清楚吗？
- [ ] 每一个新设定都对应一个玩法吗？
- [ ] 每一场的新专名不超过一个吗？
- [ ] 有没有霸总腔、油腻台词、大段说教？
- [ ] 玩家选不同选项，后面的台词都还接得上吗？
- [ ] （翻译阶段）中文有没有翻译腔或古风词？大声读一遍。
