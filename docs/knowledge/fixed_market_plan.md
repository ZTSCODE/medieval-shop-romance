# 固定交易区与来源动画

## 本轮范围

- 保持 Godot 2D 卡牌棋盘、上方客人、120 秒一天和 Esc 暂停。
- 底部固定货源、出售投卡区，移除棋盘上的货源卡。初始 8 张卡牌、4 叠。
- 所有商品、货币仍为注册卡牌；临时定价为进货 1 金币、普通出售 1 金币、交付客人 2 金币。
- 客人按 3 秒首客、12 秒间隔进入，最多同时 3 位。每位耐心 55 秒，独立进度条、秒数与低耐心状态。
- 新客人从对应等待槽上方进入；交易产物从货源、出售区或付款客人处飞出。
- 本轮不打包，运行本地 Godot 工程。

## 模块约定

`ShopSession` 处理固定交易的预览和提交，先注册产物，再发出 `outputs_created(card_ids, source_id)`，最后通知状态改变。来源 ID 为固定菜单 ID 或客人卡牌 ID。模型不依赖屏幕坐标。

`MarketDock` 绘制固定投卡区，提供屏幕矩形、来源点和接受/拒绝反馈。`CustomerLane` 提供客人实际可见位置、耐心条及入场动画。

`TableInteraction` 在状态刷新前接收来源事件，创建 `CardFlight`，将产物卡放到屏幕动画层。卡片沿弧线飞到模型选定的棋盘空位；飞行结束回到棋盘层，恢复抓取。镜头变动时终点按当前镜头换算，来源保留交易发生时的位置。

拖拽取消只恢复被抓起的原牌叠，保留其他正在发生的来客和已提交交易。暂停由场景树统一冻结输入、客人计时、飞行和日进度。没有撤销历史。

## 验证

- 规则：有效/无效交易、真实卡牌数量、余牌归位、容量边界、同时三客、独立耐心、来源事件顺序。
- 引擎输入：固定区拖放、产物首帧来源/飞行中段/落地、飞行中暂停、错误物品拒绝、取消不回滚新客、镜头缩放和平移。
- 画面：实际 Godot 窗口截图，检查耐心条、菜单文字、三客布局和产物落点。
- 交付：提供直接运行工程的入口，保留旧 EXE 的哈希，不执行导出。
