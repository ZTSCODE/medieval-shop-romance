# 按选定图修正纸张 UI

## 用户反馈与方法

2026-09-18，用户指出实机与选定粉色概念图明显不同，并明确指定制作顺序：每张纸的形状蒙版 → 每个蒙版赋予纹理 → 每张纸的阴影蒙版 → 各纸独立颜色 → 多层叠加。

上一轮失败点是纹理缩得过小并镜像重复成花纹；规则边条和上下色带代替了独立纸张；姓名条、继续按钮、宋体字形和字幕占比也偏离原图。技术检查通过没有验证这些视觉关系。

## 本轮实施

1. 以本轮用户附图 `codex-clipboard-2e49e2e7-78ac-4e4e-a30a-184c370d7f80.png` 为唯一外观基准。单独生成前纸、两张底纸、姓名条和按钮的白色形状蒙版；单独生成对应阴影蒙版、中性笔触纹理及浅色笔线蒙版。
2. 通过 Godot 分层材质裁切平铺纹理，每层独立颜色、微偏移及轻微角度。形状蒙版的角部保持固定尺度，内纸纹按纸面坐标平铺；不向文字或立绘套纸材质。离屏高分辨率缓存只缓存实际合成结果，尺寸改变重新绘制。
3. 恢复约3.5:1字幕纸身、较大的宋体字幕、叠上缘的姓名纸条和压右下缘的继续按钮。卡牌标题纸条改为居中小纸签，保留112×184游戏足迹与近景透明人物。
4. 继续使用每帧独立绘制的纸张舒展图。响应式改变高度时仅拼接同一帧的竖向中段，上下折面等比；不插帧、不压扁图片、不用淡入替代。
5. 先输出与参考同尺寸的 Godot 合成对照，再做实际游戏截图和交互、暂停、分辨率及存读档检查。最终外观需要用户看实际效果评价。

## 范围

不更改剧情、物品、信使离场或存档结构。用户已启动的游戏进程不强制关闭；测试使用独立进程和隔离存档。本轮仍不打包。

## 生产目录与实际实现

依照项目约定，生产资源归档到 `assets/art/ui/rose_modular/layers_v2/`。`rose_reference_v2/` 保留生成过程的原始归档，不再作为运行时入口。

- 6 张纸形蒙版：卡底、字幕前纸、两种底纸、姓名纸条、按钮。
- 6 张独立阴影蒙版，使用 alpha 表示强弱。黑色 RGB 不参与形状覆盖率计算。
- 1 张中性笔触平铺纹理，每层独立颜色和纹理相位。
- 2 张独立浅色笔线蒙版；纸纹和纸形无需重新绘制即可改变笔线颜色。

`layout.json` 的每层包含形状、阴影、纹理、笔线引用、颜色、位移和角度。各蒙版保留原始像素；纸面近不透明 alpha 在材质中补实，阴影保留渐变。生成器未严格保持的1像素画幅差及阴影偏移通过注册区域对齐，没有拉伸整张纸图。

Godot 分别合成这些图层，按当前尺寸和像素倍率生成透明缓存；卡牌与卡名纸签至少4倍采样。尺寸改变重新合成，纸纹始终独立按固定尺度平铺；纸张材质不附到父级，因此不会影响人物或文字。正文、姓名和按钮使用本机可用的 Noto Serif SC 字体，其他原 UI 字体维持原设置。

提示词与原始来源分别在生产目录的 `front-materials.source.json`、`backing-provenance.json`、`name-buttons.source.json`。本轮使用内置 image_gen，15 张生产素材各自生成；没有可选模型/质量档参数，未虚构此项设置。

原生对照图 `work/rose-reference-native/reference-layout.png` 由实际游戏材质和卡牌控件绘制，尺寸1672×941；实际游戏截图位于同目录。对照图用于核对美术，不增加游戏内调试界面。
