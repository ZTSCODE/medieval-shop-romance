# 基础机制补齐计划

这是上一轮基础机制计划；用户随后要求配方/人物移出 Esc、修复分辨率适配，最新入口与时间行为以 `display_journal_fix_plan.md` 为准。

## 用户本轮要求

补齐窗口模式、音频、语言设置，保存和读取进度，已发现配方与 NPC 好感查看，并明确集中本地化文本和稳定内容代号的项目规则。保持 Godot 2D、120 秒一天、暂停冻结世界、无撤销与不打包。

## 实现顺序与模块

1. **内容与文本**：`ContentCatalog` 统一内容定义与代号，`PlayerProgress` 保存已发现组合和已遇见角色；当前中文文本合入 `localization/game.csv`，补齐英文。
2. **设置与文件**：`GameSettings` 管理窗口、音量、静音和语言，独立保存。`SaveStore` 负责带版本和校验的 JSON 文件、临时写入与有效备份。
3. **游戏快照**：`GameSnapshot` 转换牌叠位置、卡牌身份、客人剩余耐心、营业状态、日进度、镜头与人物/配方记录。先验证完整快照，再一次性恢复；不存节点对象或翻译文本。
4. **菜单**：Esc 主菜单提供继续、存取、设置、配方与人物入口。子页可以返回，查看期间暂停。保持正常游戏画面简洁；R/N 可打开对应记录。
5. **实际记录**：成功执行现有组合后发现对应配方；占位熟客使用固定角色代号再次来访。暂用交付一次加 1 点好感验证基础流程，角色内容、正式数值和剧情门槛不在本轮决定。
6. **验证**：设置持久化和即时生效、完整存读一致性、损坏/错误版本拒绝、备份恢复、不同语言、配方发现、重复来访、好感保存、暂停与原有交易回归。只运行工程，不导出。

## 存档行为

存档槽结构已向用户询问，本轮在尚无偏好答复时采用并告知默认方案：1 份自动档和 3 份手动档；界面仍可收敛为单进度。自动保存等待拖拽结束，每 30 秒游玩时间、跨天和正常退出时保存已提交的交易结果；重新进入时自动读取并暂停，等待玩家继续。离线期间不推进日子、客人或耐心。

## 边界与风险

本轮图鉴登记现有已实现的组合，不预填尚不存在的烹饪配方。NPC 使用占位身份验证关系记录，不加入未经确认的人物故事。音乐音量预留通道，当前仍只有交互音效。旧 EXE 保留，最新功能从 Godot 工程运行。
